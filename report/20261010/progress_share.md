## 3. DeepSeek Harness を挟んだ検証

DeepSeek が公開したオープンソースのエージェント実行基盤（`dsh`）に、手元の Gemma だけを使って解かせました。条件は次のとおりです。

- Web は使わない
- サンドボックスの中で、ワークスペース内だけ書き込める
- 参照解を使わない検証器を道具として渡す

| 条件 | 元問題 28（元の返り値の形） | 雛形外 11 |
|---|---:|---:|
| 未学習の 12B-it 単独 | 3 | 3 |
| 未学習の 12B-it + DeepSeek Harness | 5 | 4 |
| 学習した 12B FFT 単独 | 20 | 0 |
| 学習した 12B FFT + DeepSeek Harness | 0 | 0 |
| **FFT の単独の解と DeepSeek Harness の解から、検証器で選ぶ** | **22** | **4** |

- **ハーネスは学習の代わりにならない。** 未学習のモデルは、ツールを数十回使って試し直しても少ししか伸びません。
  ライブラリの使い方で詰まったのは、検証 220 回中 1 回だけでした。足りないのは定式化と解法の知識です。
- **学習した FFT は汎用のエージェント基盤に乗らない。** ツールを 1 回も呼ばず、問題ファイルを読めませんでした。
  一発回答だけを学習した結果、ツール呼び出しの形を失っています。
- **汎用のエージェントは良い解を守らない。** FFT の正解を初版として渡すと、「改善」のつもりで手を入れて 5 問を壊しました。
- **検証器で選べば両方の良いところを取れる。** 参照解を使わない検証器で、可行で目的値の良い方を選ぶ形です。
  学習した種別では FFT の解を守りつつ汎用モデルの改善を拾い（20 → 22）、学習していない種別では汎用モデルの解を使えます（0 → 4）。

## 4. 3 月の構成への含意

1. student（学習済みの 4B / 12B）の一発回答を、参照解を使わない検証器で確かめる。
2. 通らなければ、大きいモデル、または汎用のエージェント（DeepSeek Harness など）に回し、検証器で一番良い版を採る。
3. 学習していない種別は、対応表で判定して最初から汎用のエージェントに回す。

汎用のエージェントを回すのは student が失敗した問題だけなので、費用は限られます。この段階式を保存済みの解に当てはめると、
元問題 28 問は 22 問（汎用のエージェントを回したのは FFT が検証で落ちた 8 問だけ）、雛形外 11 問は 4 問で、全部作ってから選ぶ
場合と同じ値でした（RESCORE 38.6 節）。
student にツールを使わせたい場合は、Opus の「書く → 実行 → 検証 → 直す」の試行の記録（21 本）を学習に入れるのが次の候補です。
