## 3. DeepSeek Harness を挟んだ検証

DeepSeek が公開したオープンソースのエージェント実行基盤（`dsh`）に、手元の Gemma だけを使って解かせました。条件は次のとおりです。

- Web は使わない
- サンドボックスの中で、ワークスペース内だけ書き込める
- 参照解を使わない検証器を道具として渡す

| 条件 | 元問題 28（元の返り値の形） | 雛形外 11 |
|---|---:|---:|
| 未学習の 12B-it 単独 | 3 | 3 |
| 未学習の 12B-it + DeepSeek Harness | 5 | 4 |
| 学習した 12B FFT 単独 | 20 | 0 |
| 学習した 12B FFT + DeepSeek Harness | 0 | 0 |
| **FFT の単独の解と DeepSeek Harness の解から、検証器で選ぶ** | **22** | **4** |

- **ハーネスは学習の代わりにならない。** 未学習のモデルは、ツールを数十回使って試し直しても少ししか伸びません。
  ライブラリの使い方で詰まったのは、検証 220 回中 1 回だけでした。足りないのは定式化と解法の知識です。
- **学習した FFT は汎用のエージェント基盤に乗らない。** ツールを 1 回も呼ばず、問題ファイルを読めませんでした。
  一発回答だけを学習した結果、ツール呼び出しの形を失っています。
- **汎用のエージェントは良い解を守らない。** FFT の正解を初版として渡すと、「改善」のつもりで手を入れて 5 問を壊しました。
- **検証器で選べば両方の良いところを取れる。** 参照解を使わない検証器で、可行で目的値の良い方を選ぶ形です。
  学習した種別では FFT の解を守りつつ汎用モデルの改善を拾い（20 → 22）、学習していない種別では汎用モデルの解を使えます（0 → 4）。

## 4. 3 月の構成への含意

1. student（学習済みの 4B / 12B）の一発回答を、参照解を使わない検証器で確かめる。
2. 通らなければ、大きいモデル、または汎用のエージェント（DeepSeek Harness など）に回し、検証器で一番良い版を採る。
3. 学習していない種別は、対応表で判定して最初から汎用のエージェントに回す。

汎用のエージェントを回すのは student が失敗した問題だけなので、費用は限られます。この段階式を保存済みの解に当てはめると、
元問題 28 問は 22 問、雛形外 11 問は 4 問でした（RESCORE 38.6 節）。

**ただし、実際に通しで動かすと元問題 18 問・雛形外 3 問で、効果は確かめられませんでした**（RESCORE 38.7 節）。原因は 3 つです。

- student（FFT）の答えが、前の回と変わった（20 → 18）。
- 汎用のエージェントは、student が落ちた 5 問を 1 問も救えなかった。
- 対応表の種別の判定が粗く、学習していない雛形外の問題の多くを student に回した。

そこで、student（FFT）自身に 1 問あたり 4 本（温度 0 を 1 本、温度 0.7 を 3 本）書かせ、検証器で 1 本選ぶ形を試しました。
元問題 28 問で、同じ回の温度 0 の 1 本は 19 問、4 本から選ぶと **22 問**（+3、落とした問題なし）です（RESCORE 38.8 節）。
汎用のエージェントを回すより安く、効果も確かでした。3 月の構成は次の順にします。

1. student に複数本書かせる。
2. 検証器で 1 本選ぶ。
3. それでも全部落ちたときだけ、大きいモデルか汎用のエージェントに回す。

残る課題は、種別の判定を instance の形で細かくすること（学習していない雛形外の問題を、正しく汎用のエージェントに回すため）です。
student にツールを使わせたい場合は、Opus の「書く → 実行 → 検証 → 直す」の試行の記録（21 本）を学習に入れるのが次の候補です。

## 5. 現場の PC での動作要件（10/7 会議 3.4 節、RESCORE 35 章）

学習済みの 4B（v1 データの LoRA）を、量子化（Q8_0、4.2 GiB）して、GPU なし・CPU 8 コアだけで動かしました（llama.cpp）。

| 項目 | 値 |

| 正解（大規模生成テストから、学習した 17 種別を 1 問ずつ） | 15 / 17（同じ問題で GPU・bf16 の 4B は 14。量子化と CPU 実行による劣化なし） |
| 1 問の所要（生成 + ソルバー、中央値） | 約 9 分（233〜1,140 秒） |
| 出力の生成速度（8 スレッド） | 約 12.5 token/秒 |

- **要件の目安:** メモリ 16 GB 以上、CPU 8 コア以上、GPU は不要です。大規模問題 1 問を 10 分前後で解けます。
- **注意:** ソルバーの解の質は、使える CPU 時間で変わります。コア数の少ない PC や、他の重い処理と並べて使う場合は、ソルバーの
  時間上限を延ばす必要があるかもしれません。
