## 実施した内容

### 概要

引き継いだ DSPy + GEPA のプロンプト最適化プロジェクト（最適化問題 100 問に対して solve() コードを生成させ、参照解と照合して採点する）について、まず評価基盤を信頼できる状態に直し、その上で「プロンプト最適化」と「小型モデルへの蒸留」の二つの方向を同じ物差しで比べた。

結果は次の三点に要約できる。

1. 引き継ぎ時点の「GEPA で改善」は採点系の欠陥への適応で、採点系を直すと初期プロンプトと区別できなかった。修正済み採点系で再学習した GEPA は Qwen3.8 でのみ有意に効くが、効果は学習で見た問題種別に限られ、指示文は 34KB に膨らむ。
2. 文脈なしの Claude Fable 5.1 が 140 問中 138 問を正解し（満点 1.5 に対し 1.494）、この問題集はプロンプトで伸ばせる余地がそもそも小さい。
3. 正解コードを教師に 4B モデルを LoRA 学習すると、学習した 28 種別の未知 instance では Fable と同等（1.487〜1.504）を出力 1/10、所要 1/12 で達成した。ただし種別の外では素のモデルを下回る。

### 評価基盤の整備

引き継いだ採点系には、モデルの出力とは無関係にスコアを歪める欠陥が複数あった。修正内容と影響を表 1 にまとめる。保存済みの生成コードを再実行して採点し直す仕組みを作り、修正のたびに LLM を回さずに全条件を再採点できるようにした。

表 1: 採点系の欠陥と修正

| 欠陥 | 影響 | 修正 |
|---|---|---|
| 27 種別中 8 種別にしか制約チェッカーがなく、70 問が一律減点 | 400 レコード中 198 件が unverified（実際は 9 割が正解） | 20 種別のチェッカーを追加。unverified 198 → 4 |
| verified フラグが無条件に上書きされる | 不正解に満点 | 上書きを除去 |
| サンドボックスが `from scipy.optimize import ...` や numpy 型を扱えない | 実行エラー扱いが多数。Phase E の見かけの優位の主因 | import の解決、numpy 値の変換、組み込み関数の補充 |
| 参照解と同じ形の解しか読めない | 正しい解を infeasible と判定 | 「解析してから検証する」形状チェッカー |

評価用の問題集も作り直した。既存 100 問のうち 28 問を雛形にして、厳密ソルバー（CP-SAT、線形計画、全列挙など）で最適値を計算した新しい instance を 5 問ずつ、計 140 問生成した。この 140 問は GEPA の学習にも demo にも使われていないホールドアウトで、参照解の正しさが保証されている。以降の評価はすべてこの 140 問と修正済み採点系で行い、条件間の差は paired bootstrap の 95% 信頼区間で判定した。

また、GPU サーバーの Slurm でモデル別・条件別に 1 GPU ずつジョブを流す手順を整え、Qwen3.8 の思考が出力枠 32k で切れて本文が空になる問題（140 問中 35 問）を確認したので、比較の既定を出力枠 65,536 に変えた。

### プロンプト最適化（GEPA）の再評価

修正済み採点系で、指示文の 6 条件を Qwen3.6-27B / Qwen3.8-27B で測った（表 2、図 1）。before は初期指示文、Phase E は引き継いだ GEPA 学習済み指示文、compact は初期指示文を共通原則に圧縮した 1.8KB の版、modular は compact に分野別の補足を実行時に足す版、再学習 GEPA は compact を初期値に修正済み採点系で学習し直した版である。表中の demo は、指示文の後に付ける few-shot 例 2 件を指す。Phase E の学習時に GEPA が訓練問題から採用した、単一機械ジョブ順序決定（動的計画法、prob_001）と基本 VRP（混合整数計画、prob_021）の 2 問について、問題文とその正解コード（1.6KB と 9.0KB）を入出力例として与えるもので、before 以外の 5 条件はすべて同じ 2 件を共有する。before + demo は、この demo だけの効果を指示文の効果から切り分けるための対照条件である。

表 2: 生成 140 問の平均スコア（満点 1.5、出力枠 65,536）

| 条件 | 指示文 | Qwen3.6 | Qwen3.8 |
|---|---|---:|---:|
| before | 1.5KB | 1.354 | 1.220 |
| before + demo | 1.5KB + demo | 1.382 | 1.274 |
| Phase E（引き継ぎ時） | 17.3KB + demo | 1.396 | 1.306 |
| compact | 1.8KB + demo | 1.425 | 1.265 |
| modular | compact + 分野補足 | 1.369 | 1.247 |
| 再学習 GEPA | 33.9KB + demo | 1.440 | 1.389 |

図 1: 生成 140 問の条件別平均スコア（assets/score_by_condition.png）

Phase E と before、compact、modular の差はどちらのモデルでも信頼区間が 0 を含む。引き継ぎ時に報告されていた Phase E の優位は、採点系の欠陥に適応した結果だった。

再学習 GEPA は 2 GPU で 11 時間 22 分かかり、Qwen3.8 では before に +0.17 [+0.05, +0.30]、compact に +0.12 [+0.02, +0.23] で有意、Qwen3.6 では compact と差がない（+0.02）。Qwen3.8 での利得は、細かい規則が思考を短くして枠切れを 13 問から 3 問に減らした効果と、返却形式の取り違えの減少が中身である。効果は学習で見た雛形の未知 instance に集中し（Qwen3.8 で +0.20、有意）、見ていない雛形では 0 と区別できない（+0.02）。

学習の経過を図 2 に示す。検証 13 問は反復 152 で満点に達して飽和し、残る 384 反復は予算を消費しただけだった。GEPA の既定の反省プロンプトは「ドメイン固有の事実をすべて指示文に含めよ」と指示しており、指示文が訓練問題固有の規則の列挙になるのはこの設計の帰結である。

図 2: 再学習 GEPA の検証スコアの推移（assets/gepa_val_curve.png）

これらを踏まえ、既定の指示文を compact に、モデル比較の既定を出力枠 65,536 に切り替えた。

### 上限の確認: Claude Fable 5.1

同じ 140 問を、プロジェクトの文脈を持たない Claude Fable 5.1 に問題文だけ渡して解かせると、138 問が正解で平均 1.494 だった。外した 2 問も目的値は参照と一致している。Qwen3.6 の最良条件との差は +0.07 [+0.01, +0.14] にとどまり、この問題集でプロンプト最適化が埋められる余地は Qwen3.6 で 0.07 前後、Qwen3.8 で 0.2 前後しかない。後者の大半は思考予算の問題である。

### 蒸留の検証: 4B solver の SFT

Fable と Qwen の正解コードを教師にして、Agents-A1-4B（4.6B、Qwen3.5 系）をこの問題集専用の solver に LoRA 学習した。教師コードを新しい instance で実行して正解を再確認した (問題文, コード) 対だけを学習に使い（6,720 対中 6,619 対が残った）、入力は参照値を含まない問題文、出力はコードのみで思考文を持たない。学習は H200 1 枚で 2 時間 6 分である。結果を表 3 に示す。

表 3: 特化 4B の結果（思考なし、出力枠 6,144）

| 評価集合 | 条件 | 平均 | 正解 / 問題数 | 平均出力トークン |
|---|---|---:|---:|---:|
| SFT テスト 140 問（学習した 28 雛形の未知 instance） | 素の 4B | 0.723 | 64 / 140 | 1,776 |
| 同上 | SFT 4B | 1.487 | 138 / 140 | 470 |
| 生成 140 問（Qwen・Fable と同じ集合） | SFT 4B | 1.504 | 140 / 140 | 472 |
| 雛形外 70 問（学習に種別ごと現れない） | 素の 4B | 0.602 | 27 / 70 | 2,428 |
| 同上 | SFT 4B | 0.430 | 18 / 70 | 717 |

学習した種別の未知 instance では素の 4B から +0.76 [+0.63, +0.90] で、Qwen3.6 compact を有意に上回り Fable と同等になった。所要は 140 問で 5 分である（Qwen3.6 は 1 時間、Qwen3.8 は 3〜4 時間）。一方、雛形外 70 問では −0.17 [−0.43, +0.09] と向きが負で、学習データの表層パターン（タプル展開での辺の読み方、例外時に固定値を返す fallback）を別種別に当てはめる失敗が増えた。特化 SFT は「この 28 種別を解く能力」であり、対象を広げるには雛形を足して再学習する必要がある。

推論時の chat template も結果を左右した。Qwen3 系のテンプレートは学習データに空の思考ブロックを描画するため、既定設定で推論すると学習で見ていない状態から思考を始めて枠を使い切る（平均 5,465 トークン、平均 0.558）。`enable_thinking: false` で学習時と同じ描画にして初めて 1.487 になる。

### 蒸留元・土台モデルの選定

より大きい土台の候補として Gemma 4 12B と Ministral 3 14B Reasoning を、4B と同じ入力形式で zero-shot 評価した（表 4）。Gemma 4 は思考なしで Qwen3.8 の各条件（1.22〜1.31）と同程度に解け、思考ありでは 139 問が枠切れになる。Ministral は思考が収束するが 1 問平均 15k トークンを使って正解が 23 問少ない。生成 140 問での差は +0.20 [+0.10, +0.31] で有意であり、SFT の土台は Gemma 4 12B（思考なし）で進める判断とした。

表 4: 候補モデルの zero-shot 結果（思考なし条件は出力枠 6,144、思考あり条件は 65,536。雛形外 72 問は表 3 の 70 問に参照解に欠陥のある 2 問を含めたもの）

## 今週の予定

- Gemma 4 12B を土台に同じ検証済みデータで SFT し、4B と同じ 3 つの評価集合で比べる（土台は決定済み、学習は未着手）
- 雛形外への汎化を伸ばすため、雛形を追加して学習データの種別を広げる
- GEPA は雛形を学習用と評価用に分けて回し、見ていない種別への効果を直接測る。反省プロンプトの「固有事実をすべて含めよ」を一般原則優先に差し替えた条件も並べる
- 再学習 GEPA を出力枠 32k で評価し、利得が「早く答えさせる」効果だけかを切り分ける
